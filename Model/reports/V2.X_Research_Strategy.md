## 八、V1.8 根因诊断与重新设计（2026-06-26）

### 背景

V1.8 原始设计目标：通过因子重要性剪枝（Factor Importance Pruning），在 warmup 阶段累积每个因子的梯度重要性，warmup 结束后保留 Top 80% 最重要的因子，其余因子通过 mask 置零。预期效果是去除噪声因子，提升信噪比。

V1.8 回测结果显示 **与 V1.0 结果完全一致（IC 差异 0%，Top 1 差异 0%）**，初步结论为"因子剪枝完全无效"。

### 根因分析

经逐行代码审查，发现 V1.8 实现存在**致命 Bug**，导致因子剪枝从始至终从未实际执行：

#### Bug 1: 梯度采集 Hook 时机错误（致命）

V1.8 在 `on_train_epoch_end()` 中采集第一层权重的梯度来累积因子重要性：

```python
def on_train_epoch_end(self):
    if current_epoch < warmup_epochs:
        first_layer = self.model.input_layer[0]
        if first_layer.weight.grad is not None:  # ← 永远为 None！
            ...
```

**问题**：PyTorch Lightning 的每个 batch 训练循环中，`optimizer.zero_grad()` 在 `optimizer.step()` 之后立即执行。当 `on_train_epoch_end` 触发时，所有参数的 `.grad` 早已被清零。因此 `first_layer.weight.grad is not None` **永远为 False**，`factor_importance` 始终保持全零张量。

```
PyTorch Lightning 单 batch 生命周期（V1.8 原 Bug）:
  training_step() → backward() → [.grad 存在]
    → optimizer.step()
    → optimizer.zero_grad()        ← .grad 被清除
  ...（所有 batch 结束）
  → on_train_epoch_end()           ← .grad = None  永远采集不到！
```

#### Bug 2: 静默失败的保护逻辑

在 warmup 结束（epoch 5）时，V1.8 有一个保护判断：

```python
if current_epoch == warmup_epochs:
    importance = self.model.factor_importance  # 全零张量
    if importance.sum() == 0:                  # ← True！直接返回
        return                                  # ← 静默跳过剪枝
```

这个逻辑本意是防止空因子集，但由于 `factor_importance` 始终全零，它每次都触发提前返回，**`prune_applied` 永远为 False，`factor_mask` 永远全 1（不剪枝）**。整个剪枝代码成为摆设。

#### Bug 3: `prune_applied` 使用普通 Python bool

```python
self.prune_applied = False  # 不会写入 state_dict
```

PyTorch `register_buffer` 会将张量写入 `state_dict`，在 checkpoint 保存/恢复和 SWA 中正确传递。普通的 `bool` 属性不会被序列化，如果 checkpoint 恢复或 SWA 切换模型权重，剪枝状态会丢失。

### 重新设计方案（已实施于 V1.8 model.py）

#### 修复 1: 梯度采集移至 `on_before_optimizer_step`

```python
def on_before_optimizer_step(self, optimizer):
    # ── 梯度裁剪（原有逻辑）──
    if params.gradient_clip_val is not None and params.gradient_clip_val > 0:
        torch.nn.utils.clip_grad_norm_(self.parameters(), max_norm=params.gradient_clip_val)

    # ── V1.8 因子重要性累积（修复：在此 Hook 中梯度仍存在）──
    if (params.factor_prune_enabled
        and self.model.prune_phase.item() == 0
        and self.current_epoch < params.factor_prune_warmup_epochs):
        first_linear = self.model.input_layer[0]
        if first_linear.weight.grad is not None:    # 梯度存在！
            weight_l1 = first_linear.weight.data.abs().sum(dim=0)   # 权重 L1
            grad_l1   = first_linear.weight.grad.abs().sum(dim=0)   # 梯度 L1
            step_importance = (weight_l1 + grad_l1).detach().cpu()
            self.model.factor_importance += step_importance
```

**关键改进**：
- 采集时机从 `on_train_epoch_end`（梯度已清除）移至 `on_before_optimizer_step`（梯度存在）
- 重要性度量从单一梯度 L1 改为 **权重 L1 + 梯度 L1**，双重证据更稳健
  - 权重范数反映"该因子在训练中积累的连接强度"
  - 梯度范数反映"该因子对当前 batch 的边际贡献"
- 使用 `.detach().cpu()` 避免 GPU 显存累积

#### 修复 2: `prune_phase` 使用 buffer 替代普通 bool

```python
# 修复前
self.prune_applied = False  # 不序列化

# 修复后
self.register_buffer('prune_phase', torch.tensor(0))  # 序列化
# 0 = warmup 阶段（累积重要性）
# 1 = 已剪枝（forward 启用 mask）
```

#### 修复 3: `on_train_epoch_end` 只做剪枝判断

```python
def on_train_epoch_end(self):
    if not params.factor_prune_enabled or self.model.prune_phase.item() == 1:
        return
    # warmup 期间：梯度采集已在 on_before_optimizer_step 完成
    if self.current_epoch < params.factor_prune_warmup_epochs - 1:
        return
    # warmup 最后一个 epoch：执行剪枝
    if self.current_epoch == params.factor_prune_warmup_epochs - 1:
        importance = self.model.factor_importance
        if importance.sum() == 0:
            print("[V1.8] WARNING: factor_importance is all-zero, pruning skipped.")
            return
        keep_n = max(1, int(self.model.input_dim * params.factor_prune_keep_ratio))
        _, top_indices = torch.topk(importance, keep_n)
        new_mask = torch.zeros(self.model.input_dim, device=self.model.factor_mask.device)
        new_mask[top_indices] = 1.0
        self.model.factor_mask.copy_(new_mask)
        self.model.prune_phase.fill_(1)  # 标记完成，后续 epoch 启用 mask
        # 打印 Top-5 保留因子索引和重要性，方便验证剪枝质量
```

#### 修复 4: `PredictModel.forward` 启用 mask

```python
def forward(self, tsdata):
    x = tsdata.float()
    if self.prune_phase.item() == 1:       # 剪枝后才启用
        x = x * self.factor_mask.view(1, -1)  # 被剪枝因子置零
    ...
```

### 修复后预期行为

| 阶段 | Epoch | 行为 |
|------|:-----:|------|
| Warmup | 0–3 | 全因子训练 + 每 batch 在 `on_before_optimizer_step` 累积 `factor_importance`（权重 L1 + 梯度 L1） |
| 剪枝 | 4（结束时） | 基于累积 importance 排序，保留 Top 80% 因子，其余 mask 置零。打印 Top-5 重要性日志 |
| 剪枝后 | 5–29 | 仅使用选中因子训练（`forward` 中 `x = x * factor_mask`），被剪枝因子的梯度不影响后续层 |

### 回归风险与兼容性

- **与 V2.0 Baseline 的关系**：V1.8 重新设计后的因子剪枝是一个独立维度，可叠加到 V2.0 的融合配置上
- **与 V2.8（梯度中心化）的交互**：两者都在 `on_before_optimizer_step` 中执行。V2.8 的梯度中心化应在 V1.8 的重要性累积**之前**执行（GC 修改梯度 → 重要性基于 GC 后的梯度）
- **SWA 兼容性**：`factor_mask` 和 `prune_phase` 均为 buffer，SWA 会自动继承剪枝状态
- **Checkpoint 恢复**：`prune_phase` 序列化后，checkpoint 加载可正确恢复剪枝状态

### V1.8 重新评估计划

重新设计后的 V1.8 需重新运行完整回测，验证：
1. 因子剪枝是否真正触发（检查日志中的 `[V1.8 Factor Pruning]` 输出）
2. 剪枝后 IC/Top_Return 与 V1.0 是否有差异
3. 保留的因子列表是否具有经济含义

## 二、V2.X 实验矩阵

实验分为四个方向：**多任务损失优化**（V2.1–V2.2）、**自适应正则化**（V2.3–V2.4）、**训练策略**（V2.5–V2.6）、**数据与特征**（V2.7–V2.8）。

### Part A: 多任务损失优化（V2.1 – V2.2）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V2.1** | Kendall 不确定性加权 | 用 3 个可学习 log-variance 参数替代 softmax 权重，L = Σ(Lᵢ/(2σ²ᵢ) + log(σᵢ)) | 不确定性加权能更自然地处理多周期噪声差异，V7.2 已验证 TR +8.8% | log(σ) 项可能主导训练早期 |
| **V2.2** | Top-20% WPCC | 仅在预测打分前 20% 的股票上计算 WPCC | 强制模型优化头部排序，直接对齐 Top 1/Top 500 目标 | 可能降低全市场 IC（尾部排序退化） |

**V2.1 详细设计（Kendall 不确定性加权）**:
- 目标：用任务依赖的不确定性自动平衡 1d/5d/10d 损失，替代 V1.2 的 softmax 权重
- 方法：定义 `self.log_sigmas = nn.Parameter(torch.zeros(3))`，通过 softplus 转为正数
- Loss: `L_total = L₁/(2σ₁²) + log(σ₁) + L₅/(2σ₅²) + log(σ₅) + L₁₀/(2σ₁₀²) + log(σ₁₀)`
- log(σ) 项作为正则化防止 σ→∞（即 loss→0）的退化解
- 与 V1.2 的差异：V1.2 学习「相对重要性」（权重和为 1.8），V2.1 学习「不确定性」（权重无上限约束但有 log 正则）
- 代码修改点: `DLLitModule.__init__()` 中定义 log_sigmas，`training_step()` 中损失聚合

**V2.2 详细设计（Top-20% WPCC）**:
- 目标：让模型的 WPCC 损失聚焦于它最看好的股票（头部 20%），而非全市场
- 方法：在每个 batch 内，对 1d/5d/10d 预测分别取 top-20% 索引，仅在这些股票上计算 WPCC
- k = max(int(0.2 × N), 10)，保证至少 10 只股票参与损失计算
- 代码修改点: `training_step()` 中 loss 计算前添加 `torch.topk` 过滤

### Part B: 自适应正则化（V2.3 – V2.4）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V2.3** | Concrete Dropout | 将固定 Dropout(0.2/0.1) 替换为可学习 dropout rate + KL 正则化 | 模型自动发现每层的最优 dropout 强度，V7.9 验证为最均衡 | 实现复杂度中等，额外的 KL 项可能与 Mixup 冲突 |
| **V2.4** | R-Drop 一致性正则化 | 同一样本 forward 两次（不同 dropout mask），在 1d 预测上添加 MSE 一致性惩罚 | 强制模型对 dropout 扰动鲁棒，正则化效果优于标准 Dropout | 双 forward 训练时间 ×1.5 |

**V2.3 详细设计（Concrete Dropout）**:
- 实现 `ConcreteDropout` 类：`nn.Module` 子类，包含可学习 `log_alpha` 参数
- Forward 时：训练阶段使用 Gumbel-Softmax 松弛采样 mask，推理阶段使用期望 dropout rate
- Regularization: KL(q||Bernoulli(0.5)) 近似，鼓励稀疏性
- 替换 `input_layer` 中的 `nn.Dropout(0.2)` 和 `hidden1` 中的 `nn.Dropout(0.1)`
- 在 `training_step` 中累加各 ConcreteDropout 层的正则化项到总 loss
- 代码修改点: 新增 `ConcreteDropout` 类，修改 `PredictModel.__init__()` 和 `forward()`，修改 `training_step()`

**V2.4 详细设计（R-Drop）**:
- 目标：同一个 (tsdata_mixed, ret_1d_mixed) pair，两次 forward 应得出一致的 1d 预测
- 方法：在 `training_step` 中对每个 batch 元素做两次 `self.model(tsdata_mixed)`
- 主损失照常计算（WPCC + 多周期权重），额外添加 `rdrop_weight * MSE(pred_1d, pred_1d_2)`
- rdrop_weight = 0.5，仅对 1d 预测做一致性约束（5d/10d 不受影响）
- 代码修改点: `training_step()` 中添加第二次 forward 和一致性损失

### Part C: 训练策略（V2.5 – V2.6）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V2.5** | CosineLR + Warmup | CosineAnnealingLR + 10 epoch Linear Warmup 替代 OneCycleLR | 平滑单周期余弦衰减避免 V1.6 重启的破坏性，同时保留余弦收敛优势 | 可能不如 OneCycleLR 的「尖峰探索」阶段 |
| **V2.6** | 大批次 + LR 缩放 | BS=16 × grad_accum=4 = 64, LR 线性缩放至 1e-3, max_lr 缩放至 2e-3 | 更大批次→更稳定梯度估计→WPCC 优化更平滑 | 可能损害泛化（大批次通用 trade-off） |

**V2.5 详细设计（CosineLR + Warmup）**:
- 实现 `CosineWarmupLR` 自定义 scheduler
- 前 warmup_epochs=10 个 epoch：线性从 0 升至 lr_max（=0.001，同 OneCycleLR 的 max_lr）
- 剩余 epoch：余弦衰减至 lr_min=1e-6
- 单周期无重启——直接区别于 V1.6 CosineWarmRestarts 的失败设计
- 代码修改点: 新增 `CosineWarmupLR` 类，修改 `configure_optimizers()` scheduler 定义

**V2.6 详细设计（大批次）**:
- BS 从 8 升至 16，grad_accum 保持 4，有效 batch = 64（原为 32）
- LR 线性缩放：0.0005 → 0.001（×2）
- OneCycleLR max_lr 同步缩放：0.001 → 0.002
- 其余不变
- 代码修改点: `parse_args()` 中 default 值，`params` 中 onecycle_max_lr

### Part D: 数据与特征（V2.7 – V2.8）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V2.7** | 截面 Rank 归一化 | 用 cross-sectional rank 归一化替代 z-score：rank/(N-1)-0.5 | 消除因子尺度差异和异常值影响，无需 winsorize，quant 领域标准做法 | Rank 变换丢失了因子值的相对距离信息 |
| **V2.8** | 梯度中心化 | optimizer.step() 前对权重矩阵梯度做零均值化 | 约束优化到正交子空间，提升训练稳定性和泛化，计算开销为零 | 可能削弱特定方向上的学习（通常无害） |

**V2.7 详细设计（Rank 归一化）**:
- 替代原 z-score 归一化路径（保留 z-score 分支以便对比）
- `normed_method = 'rank'`：`data_X = data_X.rank(pct=True) - 0.5` → 映射到 [-0.5, 0.5]
- 每个截面上每个因子独立 rank，自动处理缺失值和异常值
- 无需 winsorize（rank 天然排除了极端值影响）
- 代码修改点: `params.normed_method` 默认值，`normed_data()` 中添加 rank 分支

**V2.8 详细设计（梯度中心化）**:
- 在 `on_before_optimizer_step` 中，梯度裁剪之前执行
- 对每个参数 p（p.dim() > 1，即权重矩阵），`p.grad -= p.grad.mean(dim>=1, keepdim=True)`
- 不对 bias（1D）做中心化
- 代码修改点: `on_before_optimizer_step()` 添加 GC 步骤

> **与 V1.8 重新设计的交互**：V2.8 与 V1.8 重新设计版都在 `on_before_optimizer_step` 中操作。若二者叠加，GC 应在因子重要性累积前执行（GC 修改梯度 → 重要性基于 GC 后的梯度）。V2.8 是安全的 baseline 改进，可独立于 V1.8 评估。

## 三、实验假设优先级

| 优先级 | 实验 | 假设 | 预期效果 |
|:----:|------|------|---------|
| 1 | V2.1 (Kendall 不确定性) | 不确定性加权 > softmax 权重 | TR ↑↑, IC ↑ |
| 2 | V2.7 (Rank 归一化) | Rank 归一化解决因子异方差 | IC ↑, 稳定性 ↑ |
| 3 | V2.4 (R-Drop) | Dropout 一致性约束 > 标准 Dropout | IC ↑, 过拟合减少 |
| 4 | V2.3 (Concrete Dropout) | 可学习 dropout rate > 固定 rate | IC ↑, TR ↑ |
| 5 | V2.2 (Top-20% WPCC) | 头部聚焦损失→头部排序更准 | Top_Return ↑, IC 可能↓ |
| 6 | V2.6 (大批次) | 更稳定梯度→更好收敛 | 小幅全面提升 |
| 7 | V2.5 (CosineLR) | 平滑余弦衰减替代 OneCycle | 可能持平或小幅提升 |
| 8 | V2.8 (梯度中心化) | GC 提升训练稳定性 | 小幅提升，安全改进 |

## 五、评估框架

### 回测设置
- **回测区间**: 2025Q1 – 2026Q1（5 季度），可选扩展到 2026Q2（6 季度）
- **交叉验证**: 4-fold rolling window
- **训练窗口**: 4 年（动态滑动）
- **验证集**: 测试季度前 12 个月内随机 1/4 天数
- **测试集**: 目标季度全部交易日

### 评估指标
| 指标 | 全称 | 含义 | 计算方式 |
|------|------|------|---------|
| Top 1 年化收益 | Top-1 Annualized Return | 日选 1 只的实盘年化 | (1+日均收益)^252 - 1 |
| Top_Return | Top-500 Return | Top-500 选股超额收益 | model_res 汇总 |
| IC | Mean Rank IC | 预测排序准确性 | 各日 Rank IC 的均值 |
| ICIR | IC / IC Std | 排序信噪比 | IC 均值 / IC 标准差 |
| Top_Return 稳定性 | Top_Return Std | 收益稳定性 | 各季度 Top_Return 的标准差 |

### 对比基线
- **V2.0 绝对基线**: 融合 V1.2 + V1.7
- **V1.0 历史基线**: V1.0 = IC 0.0532, TR 1.1365, Top1 286.40%
- **V1.2 最优 TR**: TR 1.3533, Top1 341.02%
- **V1.7 最优 IC**: IC 0.0546, Top1 294.49%
