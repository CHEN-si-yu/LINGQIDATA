## 二、V1.X 实验矩阵

实验分为四个方向：**损失函数优化**（V1.1–V1.2）、**网络架构变体**（V1.3–V1.4）、**训练与优化策略**（V1.5–V1.6）、**数据与正则化**（V1.7–V1.8）。

### Part A: 损失函数优化（V1.1 – V1.2）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V1.1** | Pairwise Ranking Loss | 用成对边际排序损失替代 WPCC | 直接优化排序目标，IC 提升更直接 | O(n²) 计算开销，batch 内 pair 数爆炸 |
| **V1.2** | 可学习多周期权重 | multi_horizon_weights 改为可训练参数 | 自动学习最优权重，优于人工设定 | 权重可能退化为仅优化单一周期 |

**V1.1 详细设计（Pairwise Ranking Loss）**:
- 目标：直接优化排序，而非先优化相关性再间接优化排序
- 方法：对每个 batch 内的股票对 (i, j)，若 pred_i > pred_j 但 ret_i < ret_j，施加惩罚
- Loss: `max(0, margin - (pred_i - pred_j) * sign(ret_i - ret_j))`
- 为控制计算量，每个 batch 随机采样 min(1000, n*(n-1)/2) 对
- 保留多周期结构，每个周期独立计算 ranking loss 后加权求和
- 代码修改点: `get_loss_fn()` 函数和 `training_step()` 中的 loss 计算

**V1.2 详细设计（可学习多周期权重）**:
- 目标：让模型自动发现 1d/5d/10d 的最优权重配比
- 方法：将 `multi_horizon_weights` 定义为 `nn.Parameter` (log-space)，通过 softmax 归一化
- 初始值: log(1.0), log(0.5), log(0.3)，经 softmax 后约等于 [0.56, 0.24, 0.20]
- 权重与模型参数一起被 AdamW 优化
- 代码修改点: `DLLitModule.__init__()` 中定义可学习权重，`training_step()` 中使用

### Part B: 网络架构变体（V1.3 – V1.4）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V1.3** | 残差连接 | 在 512→256→64 层间添加残差连接 | 改善深层梯度流动，提升大网络训练效果 | 当前网络仅 3 层，残差收益可能有限 |
| **V1.4** | 超宽架构 | 1024→512→128 替代 512→256→64 | 更宽的表示空间捕获复杂因子交互 | 参数量 ×4，过拟合风险增大，训练变慢 |

**V1.3 详细设计（残差 MLP）**:
- 在 hidden1 (512→256) 和 hidden2 (256→64) 中添加残差连接
- hidden1 残差：输入 512 维，需通过线性投影到 256 维后相加
- hidden2 残差：输入 256 维，需通过线性投影到 64 维后相加
- 残差路径: `x + projection(prev_x)`
- 代码修改点: `PredictModel.__init__()` 和 `forward()`

**V1.4 详细设计（超宽架构）**:
- 各层宽度翻倍: `input→1024→512→128→3头`
- 首层 Dropout 保持 0.2，hidden1 Dropout 保持 0.1
- 其余配置完全不变
- 预期参数量从 ~0.55M 增加到 ~2.0M
- 代码修改点: `PredictModel.__init__()` 中的 Linear 维度

### Part C: 训练与优化策略（V1.5 – V1.6）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V1.5** | SAM 优化器 | Sharpness-Aware Minimization 替代 AdamW | 寻找平坦极小值，提升泛化能力和样本外 IC | 每步 2× 前向+反向传播，训练时间翻倍 |
| **V1.6** | CosineWarmRestarts | CosineAnnealingWarmRestarts 替代 OneCycleLR | 周期性重启帮助跳出局部最优 | 学习率波动可能导致训练不稳定 |

**V1.5 详细设计（SAM 优化器）**:
- 使用 SAM (Sharpness-Aware Minimization) 包装 AdamW
- SAM 参数: rho=0.05（邻域半径），adaptive=False
- SAM 两步: (1) 先沿梯度方向扰动参数，(2) 在扰动点计算梯度并更新
- 保留手动梯度裁剪（在扰动前执行）
- 代码修改点: `configure_optimizers()` 中的优化器构建，手动实现 SAM 逻辑到 `training_step()` 或 `on_before_optimizer_step()`

**V1.6 详细设计（CosineAnnealingWarmRestarts）**:
- 替换 OneCycleLR 为 `CosineAnnealingWarmRestarts`
- 参数: T_0=10 (首次重启周期), T_mult=2 (每次重启周期倍增), eta_min=1e-6
- 保留 3 epoch linear warmup（通过 `LinearLR` + `SequentialLR` 组合）
- 代码修改点: `configure_optimizers()` 中的 scheduler 定义

### Part D: 数据与正则化（V1.7 – V1.8）

| 实验 | 变量 | 修改内容 | 假设 | 风险 |
|------|------|---------|------|------|
| **V1.7** | 强 Label Smoothing | label_smooth_noise 从 0.02 提至 0.05, 加 Mixup | 更强的标签正则化防止过拟合 | 过度平滑可能掩盖真实信号 |
| **V1.8** | 因子重要性剪枝 | 基于梯度重要性保留 Top 80% 因子 | 去除噪声因子提升信噪比 | 可能丢弃弱但互补的因子 |

**V1.7 详细设计（强正则化）**:
- Label Smooth 噪声标准差从 0.02 提升到 0.05
- 额外添加 Input Mixup：以 α=0.2 的 Beta 分布混合训练样本
- Mixup 公式: `x_mix = λ*x_i + (1-λ)*x_j`, `y_mix = λ*y_i + (1-λ)*y_j`
- 仅对 1d label 做 mixup（5d/10d 保持原样）
- 代码修改点: `params.label_smooth_noise` 和 `training_step()` 或 `collate_fn()`

**V1.8 详细设计（因子重要性剪枝）**:
- warmup 阶段 (前 5 epoch) 正常训练全量因子
- warmup 结束后，计算每个因子的梯度重要性 = `mean(|grad|)` across samples
- 保留 importance 前 80% 的因子，其余置零（mask 方式）
- 后续训练仅使用选中的因子子集
- 代码修改点: `PredictModel` 中添加因子 mask，`training_step()` 中 warmup 后计算并应用 mask

> ** 2026-06-26 Bug 诊断**：回测结果显示 V1.8 与 V1.0 输出完全一致，经逐行审查发现实现存在致命 Bug：（1）梯度采集在 `on_train_epoch_end` 中执行，但此时 `.grad` 已被 `optimizer.zero_grad()` 清除，导致 `factor_importance` 始终为全零；（2）`prune_applied` 使用普通 Python bool 不会写入 `state_dict`。**V1.8 已重新设计并修正**（将梯度采集移至 `on_before_optimizer_step`，重要性度量改为权重 L1 + 梯度 L1，prune_phase 改用 buffer）。详见 V2.X_Research_Strategy.md 八。

## 八、V1.8 Bug 诊断与修正（2026-06-26 事后分析）

### 现象

V1.8 回测指标与 V1.0 **完全一致**（IC 差异 0%，Top 1 差异 0%），初步结论误判为"因子剪枝无效"。

### 根因

代码审查发现两个致命问题导致剪枝从未实际执行：

| Bug | 位置 | 症状 | 影响 |
|-----|------|------|------|
| 梯度采集时机错误 | `on_train_epoch_end` | `.grad` 已被 `zero_grad()` 清除，始终为 `None` | `factor_importance` 保持全零，剪枝条件永不满足 |
| 静默失败保护 | `importance.sum() == 0` 判断 | 全零 importance 触发提前 `return` | 无任何日志输出，`prune_applied` 始终为 `False` |
| `prune_applied` 序列化 | `self.prune_applied = False` | 普通 Python bool 不写入 `state_dict` | SWA/checkpoint 恢复会丢失剪枝状态 |

```
PyTorch Lightning 生命周期（错误设计）:
  backward() → [.grad 存在  ]
    → optimizer.step()
    → optimizer.zero_grad()     ← .grad = None
  ...
  → on_train_epoch_end()        ← 采集梯度  ❌ 永远为 None
```

### 修正

| 修正 | 内容 |
|------|------|
| 梯度采集 | 从 `on_train_epoch_end` 移至 **`on_before_optimizer_step`**（此时 `.grad` 仍存在） |
| 重要性度量 | 从单一 `grad.abs()` 升级为 **`weight.abs() + grad.abs()`**（权重范数 + 梯度范数） |
| 剪枝状态 | 从 `self.prune_applied = False`（bool） 升级为 **`self.register_buffer('prune_phase', tensor(0))`** |
| 日志 | 剪枝时打印 Top-5 保留因子索引与重要性，全零时输出 WARNING |

**修正已直接应用于 `/root/autodl-fs/lingqiData/Model/V1.8/model.py`**。
详细设计和完整的修复后代码见 **V2.X_Research_Strategy.md 八**。

### 启示

1. **所有涉及梯度的自定义逻辑必须在 `on_before_optimizer_step` 或 `on_after_backward` 中执行**，`on_train_epoch_end` 中梯度已不可用；
2. 任何"与 Baseline 完全一致"的实验结果都应首先排除实现 Bug，而非直接否定方法；
3. 此类静默失败极度危险——代码正常运行、无报错、无 NaN，唯一线索是结果完全相同。
