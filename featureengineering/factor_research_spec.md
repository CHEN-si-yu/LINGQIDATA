> 版本：v1.0  
> 适用范围：`featureengineering/src/featureengineering/factors/` 下的新因子研究、旧因子重构、候选因子筛选与评估  
> 目标读者：负责因子研究与代码实现的开发者或 AI 编程代理（包括 Claude）  
> 基础约束：本文件是研究方法规范；数据白名单、PIT、性能、注册方式和 pandas 兼容性仍以 `featureengineering/skill.md` 为强制基础规范。

## 最高优先级指令：当前阶段只做减法

> **本项目当前阶段的首要任务不是开发新因子，而是审计现有 768 个因子并做减法。**

后续接手工作的 AI Agent 必须首先完成现有因子库的压缩。除非已经用训练期和样本外证据证明现有体系缺少某一类独立信息，否则不得新增因子、不得批量生成公式变体、不得以“扩大候选集”为目标开展工作。

当前工作的目标是把：

```text
768 个来源重叠、质量不一、包含大量变体的候选因子
```

压缩为：

```text
约 30～80 个信息机制清楚、彼此相对独立、样本外稳定的核心因子
```

### 必须依次完成的五层减法

#### 第一层：删除完全重复和单调等价因子

包括但不限于：

- 数值完全相同或仅名称不同的因子。
- 正负号相反但信息完全相同的因子。
- `rank(x)` 与其 log、sqrt、幂函数等单调变体。
- 同一个 primitive 经过重复截面排名生成的多个版本。
- IC 统计、覆盖率和逐日截面排序长期完全一致的因子。

这一层只判断“是否提供新的排序或数值信息”，不因为名称或 thesis 不同而保留。

#### 第二层：删除质量不合格因子

包括：

- NaN、覆盖率或每日有效股票数不达标。
- 长期截面方差不足、唯一值过少或日变化率过低。
- 仅在极小股票子集上产生高 IC 的稀疏伪信号。
- 存在 PIT、数据到达时间、静态快照回填或未来信息风险。
- 缺少可交易解释，且无法建立独立事件研究口径的因子。

#### 第三层：删除样本外无效和不稳定因子

包括：

- 只在全样本有效、walk-forward 样本外无效的因子。
- 主要由单一年份、单一季度或少数极端日期贡献的因子。
- 不同 fold 频繁翻转方向且无法用市场状态解释的因子。
- 1d/3d/5d/10d 方向混乱，且没有明确时间结构假设的因子。
- 成本前有效、考虑换手和交易成本后失去意义的因子。

#### 第四层：删除风格重复和伪 Alpha

将候选因子对规模、估值、动量、反转、低波动、流动性、Beta、日内波动等核心风格进行残差化。

如果一个因子：

- 原始 IC 较高；
- 但 residual IC 接近 0；
- 或加入核心因子组合后没有样本外增量；

则它只是已有风格的另一种表达，不作为独立核心因子保留。

#### 第五层：删除同机制内的次优代表

在同一信息簇内，只保留少量最优代表。选择顺序为：

1. 样本外方向和 IC 更稳定。
2. residual IC 更高。
3. 覆盖率更高。
4. 换手和成本更低。
5. 机制与公式更简单。
6. PIT 和数据质量风险更低。

不因为某个因子 IC 略高但公式复杂、覆盖差或不稳定，就优先于简单稳健的代表。

### 阶段门禁

在以下交付物全部完成前，不得进入本文件后面的“新因子候选开发”阶段：

- [ ] 768 个因子的完整审计表。
- [ ] 完全重复、单调等价和高度相关因子清单。
- [ ] 覆盖率、有效股票数、截面方差和 PIT 不合格清单。
- [ ] 逐 horizon、逐年度、逐 walk-forward fold 的样本外 IC 表。
- [ ] 核心风格残差化后的 incremental IC 表。
- [ ] 按信息机制聚类后的簇及每簇代表因子。
- [ ] 建议删除、保留、条件保留和待复核的决策清单。
- [ ] 约 30～80 个核心候选因子集合。

只有当上述核心集合已经形成，并且审计结果明确指出某类信息机制缺失时，才允许从第 3～7 节选择少量 surprise、residual、regime 或 coupling 候选进行开发。

### 对 AI Agent 的直接任务定义

```text
你的首要任务不是开发新因子，而是审计现有 768 个因子并做减法。

请按照“完全重复/单调等价 → 数据质量不合格 → 样本外无效或不稳定
→ 核心风格可解释 → 同机制次优代表”的顺序逐层淘汰，最终形成约
30～80 个核心因子。

不得为了达到某个因子数量而保留弱因子；不得在完成审计前新增因子；
不得只使用全样本绝对 IC 做判断；每个保留结论必须有样本外稳定性和
增量信息证据。
```

本文件第 3～7 节中的候选因子只是一份**完成减法之后**的研究储备，不是当前阶段的立即开发任务。

## 0. 文档目标

当前项目已经拥有较大规模的经验因子库，但继续增加相似公式的边际收益正在下降。本规范的目标不是继续机械扩充因子数量，而是把因子研究从：

```text
经验公式 → 截面排名 → 与 target 计算一次全样本 IC → 保留
```

升级为：

```text
经济假设
  → 原始信息 primitive
  → 异常/残差/状态条件化
  → 明确预测周期
  → 训练期内评估
  → 样本外稳定性验证
  → 增量信息检验
  → 可交易性与成本检验
```

本规范重点解决以下问题：

1. 大量因子来自相同 OHLCV、分钟线、换手率和波动率信息，只是公式不同。
2. 很多基础因子过早转换为截面 rank，丢失了原始幅度和时序异常信息。
3. 已 rank 因子上的 log、sqrt 等单调变换不产生新的 Rank IC 信息。
4. 当前耦合因子数量较多，但部分组合缺少可证伪的机制假设。
5. 现有筛选偏向单因子全样本 IC，缺少样本外、状态依赖和增量 IC 检验。
6. 1 日 open-to-open target 噪声很大，因子周期与标签周期经常不匹配。

当前执行顺序必须是：

```text
先修正评估口径
  → 审计 768 个现有因子
  → 去重复、去无效、去不稳定、去风格冗余
  → 建立 30～80 个核心因子集
  → 识别核心集合真正缺失的信息
  → 最后才允许少量开发新因子
```

## 1. 当前因子体系快照与诊断

### 1.1 当前规模

依据 `featureengineering/fac_select_meta.json`：

- 总因子数：768。
- 保留因子数：616。
- 去除因子数：152。
- IC 样本起点：2022-01-01。
- IC 样本交易日数：1114。
- 去冗余相关阈值：0.95。
- 相关矩阵抽样交易日数：372。
- 股票池文件 `Code_num.txt` 当前包含约 1782 个代码。

静态映射到注册信息的主要类别约为：

| 类别 | 数量 | 当前特征 |
|---|---:|---|
| `price` | 205 | 日线价格、动量、反转、振幅、波动、换手等 |
| `intraday` | 203 | 分钟收益、分钟波动、时段结构、分钟指标等 |
| `coupling` | 125 | 两因子/三因子组合、共振、背离、确认 |
| `fund_flow` | 92 | 大中小单、净流入、订单结构、资金流波动 |
| `risk` | 39 | Beta、特质波动、VaR/CVaR、流动性风险等 |
| `valuation` | 35 | BP、PE、PS、股息率、估值变化等 |
| `event` | 22 | 涨跌停、极端波动、事件衰减等 |
| `timeseries` | 20 | 个股自身历史位置、时序异常等 |

`price + intraday + coupling` 合计约 533 个，说明当前因子数量很多，但信息源高度集中。768 个公式不代表 768 个独立信号。

### 1.2 当前 IC 分布不能简单解释为“全部无效”

`fac_select_meta.json` 中的 `mean_abs_ic` 是 1d/3d/5d/10d 四个 horizon 的 `abs(mean IC)` 平均，不是单独 target1d IC。

当前分布大致为：

- 中位 `mean_abs_ic`：约 0.0198。
- 380 个因子不低于 0.02。
- 147 个因子不低于 0.04。
- 28 个因子不低于 0.06。
- 最高一批约为 0.06～0.075。

这说明当前体系并非完全没有信号，但需要回答三个更重要的问题：

1. 信号是否只在某一个 horizon 有效？
2. 信号是否在不同时期或市场状态下发生方向翻转？
3. 信号是否只是低波动、规模、流动性等已有风格暴露？

### 1.3 当前值得保留并继续深挖的“种子基因”

以下不是直接认定为最终 Alpha，而是根据当前聚合 IC 结果，适合作为后续异常化、残差化和状态化研究的起点：

| 种子信号 | 当前含义 | 后续研究重点 |
|---|---|---|
| `amihud_parkinson_ratio` | 单位波动对应的非流动性成本 | 从两个 rank 的比值改成原始冲击成本残差；按流动性状态分层 |
| `margin_buy_momentum_5d` | 融资买入动量 | 剔除规模、成交额和过去收益后的异常融资需求 |
| `margin_velocity` | 融资变化速度 | 研究加速度、衰减和价格确认，而非只看速度水平 |
| `idio_vol_60` | 特质波动率 | 研究低特质波动溢价的市场状态依赖和拥挤反转 |
| `amplitude_20` | 低振幅/低风险风格 | 从绝对水平升级为振幅异常、振幅压缩和突破条件化 |
| `turnover_orthogonal_to_mv` | 对规模正交后的换手 | 继续扩展到收益、波动、上市年龄条件下的换手残差 |
| `smart_money_share` | 日内聪明资金占比 | 研究持续性、价格冲击效率和尾盘确认 |
| `min_boll_width_std_20` | 分钟布林带宽稳定性 | 研究压缩后突破方向，而不是只预测低波动溢价 |
| `limit_up_fade_10` | 涨停事件后的衰减 | 加入封板质量、成交量、流动性和市场情绪条件 |
| `lowvol_trend_efficiency_combo_20` | 低波动与趋势效率组合 | 拆解增量贡献，避免只是低波动因子的重复表达 |

### 1.4 当前相对薄弱、应改变研究方式的模块

从当前聚合统计看，以下模块平均 IC 相对偏低：

- 传统资金流绝对水平和简单比例。
- 筹码分布的静态水平、峰形状和简单动量。
- 简单技术指标的交叉、排列和一致性。
- 融券/卖空类稀疏因子。
- 在已 rank 因子上继续生成的 log/sqrt 变体。

这些模块不应简单删除，也不应继续堆叠同类公式。优先改造方向是：

```text
绝对水平 → 相对自身历史的 surprise
简单比例 → 条件期望残差
静态状态 → 变化、加速度、持续性、衰减
无条件信号 → 市场状态/流动性状态条件信号
单因子 IC → 对核心风格正交后的增量 IC
```

## 2. 研究总原则

### 2.1 一个因子必须回答五个问题

任何新因子在编码前必须明确回答：

1. **信息来源是什么？** 例如融资需求、成交冲击、尾盘压力、筹码迁移。
2. **为什么市场没有立即定价？** 例如交易限制、投资者反应不足、流动性补偿、行为偏差。
3. **信号在哪种条件下有效？** 例如高波动、缩量、趋势市场、事件发生后。
4. **预期在哪个 horizon 生效？** 1d、3d、5d、10d 中必须预先指定主周期。
5. **它相对已有因子新增了什么？** 必须指出需要对哪些核心因子做残差化或增量检验。

无法回答其中三个以上的问题，不进入开发阶段。

### 2.2 因子数量不是研究目标

禁止设定“本轮必须新增 20/50/100 个因子”的目标。研究目标应是：

- 找到新的信息源或已有信息源的新状态。
- 提升样本外 IC 稳定性。
- 提供对核心因子的增量信息。
- 降低组合换手或改善极端行情表现。

如果一轮研究只留下 2～5 个有效因子，也是成功结果。

### 2.3 方向由数据验证，机制由研究者解释

注册信息中的 `thesis` 应描述机制，不应仅写“经验上高值未来收益高”。

允许最终方向与原始假设相反，但必须记录：

- 原始方向假设。
- 训练期观察方向。
- 各样本外 fold 的方向。
- 是否存在状态翻转。

禁止为了提高全样本绝对 IC，事后随意翻转因子方向而不记录。

## 3. 方向一：从“水平因子”升级为 surprise、innovation 与 residual

这是当前体系优先级最高的研究方向。

### 3.1 为什么水平值容易失效

当前大量因子直接使用：

- 20 日平均换手率。
- 20 日振幅或波动率。
- 大单净流入比例。
- 筹码集中度。
- 融资余额或融资买入额变化。
- 分钟 RSI/MACD/BOLL 的当日统计量。

这些变量通常同时受到规模、流动性、过去收益、波动率和市场状态影响。例如大单净流入很高，可能只是因为该股票当天成交额很大；换手率很高，可能只是小盘股的长期特征。

真正可能具有预测力的是：

> 在已知规模、流动性、收益、波动和自身历史后，当前观测值仍然有多异常。

### 3.2 三种标准构造

#### A. 时序 surprise

对股票自身历史进行标准化：

```text
surprise_i,t = (x_i,t - rolling_mean_i,t-1) / rolling_std_i,t-1
```

强制要求：

- 基准窗口只能使用 `<= t` 的数据。
- 推荐先 `shift(1)` 再计算基准，避免把当天异常稀释进自身基准。
- 研究 20/60/120 日多个经济上合理的窗口，不进行无约束窗口搜索。
- 原始 `x` 必须是未截面 rank 的 primitive。

适用变量：换手、成交额、波动率、资金流、融资买入、筹码集中度、尾盘成交占比。

#### B. 条件残差

从可解释变量中剔除机械关联：

```text
x_resid = x - E[x | log_mv, amount, volatility, past_return, market_state]
```

可使用：

- 每日截面线性回归。
- 规模分桶后组内去均值。
- 滚动训练的 Ridge/Huber 回归。
- 简单、可解释的分层残差。

禁止使用当天或未来 target 参与残差模型。

#### C. 创新与加速度

```text
innovation_5  = x_t - mean(x_{t-5:t-1})
acceleration  = mean(x_{t-2:t}) - mean(x_{t-7:t-3})
decay         = recent_signal / earlier_signal
persistence   = sign_consistent_days / window
```

适合研究资金流、融资流、筹码迁移和事件衰减。

### 3.3 结合现有体系的具体候选

#### 3.3.1 价格、成交量和换手率

##### `turnover_surprise_size_neutral_20`

- Primitive：`finance.turnover_rate`。
- 构造：当天换手率相对个股过去 60 日分布的 z-score，再对 `log(total_mv)` 与过去 20 日波动率做截面残差。
- 机制：识别不是由小市值或高波动天然导致的异常换手。
- 主 horizon：1d/3d。
- 对照因子：`turnover_20`、`turnover_f_20`、`turnover_orthogonal_to_mv`。
- 验收重点：必须证明对 `turnover_orthogonal_to_mv` 仍有增量 IC。

##### `amount_shock_absorption_5`

- Primitive：成交额、当日收益、日内振幅。
- 构造：成交额 surprise 很高，但绝对收益和振幅低于条件期望时取高值。
- 机制：大成交额没有造成明显价格冲击，可能代表隐蔽吸收或筹码换手完成。
- 主 horizon：3d/5d。
- 风险：可能退化为低波动因子，必须对 `amplitude_20`、`idio_vol_60` 做残差检验。

##### `volatility_compression_surprise_20`

- Primitive：日内高低价波动、分钟 RV、ATR。
- 构造：短期波动相对个股自身长期波动显著下降，同时成交额未同步枯竭。
- 机制：有交易参与的波动压缩比单纯低波动更可能代表方向突破准备。
- 主 horizon：3d/5d。
- 对照因子：`amplitude_20`、`high_low_volatility_20`、`min_boll_width_std_20`。

#### 3.3.2 资金流

##### `big_order_flow_surprise_20`

- Primitive：大单净流入金额、大单买卖金额、总成交额。
- 构造：先用成交额、当日收益、振幅解释大单净流入，再对残差做 20 日时序 z-score。
- 机制：剔除“成交活跃自然带来大单流量”的机械关系，保留真正异常的大单需求。
- 主 horizon：1d/3d。
- 对照因子：现有大单净流入比例、`smart_money_share`、资金流动量因子。
- 禁止：仅对大单金额除以总成交额后再生成多个窗口变体。

##### `flow_price_impact_efficiency_5`

- Primitive：净主动买入、日内收益、分钟波动、成交额。
- 构造：单位净流入导致的价格变化，与该股票自身历史冲击系数比较。
- 高流入低冲击：潜在吸收/供应充足。
- 高流入高冲击：追涨或信息冲击。
- 主 horizon：1d/3d，根据状态分别检验方向。
- 必须条件化：市场波动、股票流动性、过去 5 日收益。

##### `retail_institutional_divergence_persistent_5`

- Primitive：小单与大单方向。
- 构造：不使用单日背离；要求 3～5 日持续背离，并剔除价格趋势可解释部分。
- 机制：持续的投资者类型分歧比单日订单分类噪声更可靠。
- 主 horizon：3d/5d。
- 风险：订单分类口径可能随成交额变化，必须做规模和流动性分层。

#### 3.3.3 融资融券

当前 `margin_buy_momentum_5d`、`margin_velocity` 表现较强，融资模块应作为优先深挖方向。

##### `margin_buy_demand_residual_20`

- Primitive：融资买入额、融资余额、成交额、过去收益、总市值。
- 构造：融资买入额对成交额、规模、过去 5 日收益回归后的残差。
- 机制：识别超过交易活跃度和追涨效应所能解释的杠杆需求。
- 主 horizon：3d/5d。
- PIT：必须沿用数据层已经确认的 T+1 到达/shift 口径。

##### `margin_acceleration_price_confirmation_5`

- Primitive：融资需求加速度、价格趋势、成交量。
- 构造：融资需求连续加速，但价格尚未显著上涨时定义为潜在积累；融资加速且价格已极端上涨定义为拥挤风险。
- 机制：同一融资加速在不同价格确认阶段方向可能相反。
- 主 horizon：1d/3d。
- 输出建议：分别输出 `accumulation` 与 `crowding` 两个可解释因子，不要强行揉成一个复杂公式。

##### `margin_flow_decay_after_shock`

- Primitive：融资买入 surprise。
- 构造：事件发生后的第 1～10 日衰减斜率、半衰期与价格反应。
- 机制：持续杠杆需求与一次性冲击的预测含义不同。
- 主 horizon：5d/10d。

#### 3.3.4 筹码分布

当前筹码模块大量使用集中度、峰宽、成本位置和简单变化，平均 IC 偏低。下一步应减少静态形态描述，增加迁移和价格响应。

##### `chip_cost_shift_surprise_20`

- Primitive：加权成本、成本分位点、当前价格。
- 构造：成本中枢 5 日变化相对自身 60 日变化分布的 surprise。
- 机制：异常快速的筹码成本上移/下移，比成本绝对位置更能反映新资金换手。
- 主 horizon：3d/5d。
- 对照因子：`chip_cost_momentum_20d` 及同类筹码动量。

##### `chip_concentration_price_divergence_10`

- Primitive：筹码集中度变化、价格变化、换手率。
- 构造：集中度上升但价格未上涨，或集中度下降但价格上涨，分别作为潜在吸筹/派发候选。
- 机制：筹码变化与价格反应的背离比单独集中度更有解释力。
- 主 horizon：3d/5d。
- 必须控制：低换手导致的筹码数据机械不变。

##### `chip_peak_migration_persistence_5`

- Primitive：筹码主峰位置及每日迁移。
- 构造：主峰连续同向迁移天数、迁移速度和价格相对主峰位置。
- 机制：持续迁移代表真实持仓成本重定价；单日跳动可能是估计噪声。
- 主 horizon：5d/10d。

#### 3.3.5 分钟线与日内结构

当前分钟因子数量超过 200。后续禁止继续简单增加“上午/下午均值、标准差、比值”的排列组合，优先研究价格形成过程。

##### `close_pressure_residual`

- Primitive：最后 30 分钟收益、成交占比、全天收益、市场尾盘收益。
- 构造：尾盘收益减去全天趋势、市场尾盘和成交占比可解释部分。
- 机制：异常尾盘定价压力可能包含收盘调仓、信息交易或操纵性冲击。
- 主 horizon：1d。
- 分层：高/低流动性、高/低全天收益。

##### `opening_gap_absorption`

- Primitive：隔夜跳空、开盘后 30/60 分钟收益、成交量、价差代理。
- 构造：大幅跳空后，价格是否在高成交下被吸收或继续扩散。
- 机制：跳空本身不是信号，开盘后的承接方式才决定延续或反转。
- 主 horizon：1d/3d。
- 对照因子：`overnight_gap`、`gap_ratio`、开盘强度类因子。

##### `intraday_path_efficiency_residual`

- Primitive：开收收益、分钟 RV、路径长度、最大回撤、成交额。
- 构造：在相同日收益和波动下，衡量价格路径是否单向、震荡或尾盘逆转。
- 机制：相同日收益可能由平稳信息扩散或剧烈博弈产生，后续含义不同。
- 主 horizon：1d/3d。

##### `smart_money_persistence_5`

- Primitive：现有 `smart_money_share` 的原始基础指标，而不是其最终 rank。
- 构造：连续多日水平、变化、价格冲击效率。
- 机制：持续聪明资金参与比单日高占比更可靠。
- 主 horizon：3d/5d。

## 4. 方向二：显式研究状态依赖，而不是用绝对 IC 吞掉方向翻转

### 4.1 状态依赖是当前体系的核心线索

当前若干波动、振幅和换手因子具有较大的 `mean(abs(daily IC))`，但长期平均 IC 和 ICIR没有同等幅度。这通常意味着：

- 因子在某些时期很强。
- 不同状态下方向可能相反。
- 无条件平均掩盖了条件 Alpha。

因此，不应把高 IC 波动简单解释为“强因子”，也不应直接删除。必须进行条件 IC 分析。

### 4.2 允许使用的状态变量

状态变量必须使用 PIT 合格的数据，并在 T 日收盘可知。

推荐状态：

| 状态 | 建议构造 |
|---|---|
| 市场趋势 | 全股票池等权收益的 20/60 日累计值或均线差 |
| 市场波动 | 全股票池等权收益波动、截面收益离散度 |
| 市场流动性 | 全市场成交额相对 20/60 日均值 |
| 市场广度 | 上涨股票占比、创阶段新高/新低占比 |
| 风险偏好 | 小市值相对大市值收益、低波动相对高波动收益 |
| 个股流动性 | 成交额、换手率、Amihud 分位组 |
| 个股趋势 | 过去 20/60 日收益与趋势效率 |
| 个股事件状态 | 涨跌停、极端收益、跳空、成交冲击后若干日 |

禁止使用当前静态 `stock_list.parquet` 回填历史行业。需要行业状态时，必须先取得历史 PIT 行业映射；在此之前不得重新启用已被 `factor_loader` 禁用的行业因子。

### 4.3 三种状态建模方式

#### A. 条件评估，不立即生成新因子

先分别计算：

```text
IC(factor | high_market_vol)
IC(factor | low_market_vol)
IC(factor | uptrend)
IC(factor | downtrend)
```

只有条件差异在多个训练 fold 中稳定，才进入因子生成。

#### B. 软门控

```text
gated_signal = base_signal * sigmoid(state_zscore)
```

相比 0/1 硬切换，软门控通常更稳定。`sigmoid` 可用简单单调映射近似，不要求引入深度模型。

#### C. 分拆为不同机制因子

例如融资加速：

- 低涨幅 + 融资加速：潜在积累。
- 高涨幅 + 融资加速：潜在拥挤。

建议生成两个含义清楚的因子，而不是用复杂正负条件拼成一个难以解释的总分。

### 4.4 结合现有因子的重点状态实验

| 基础因子/家族 | 必测状态 | 研究问题 |
|---|---|---|
| `amplitude_20`、`idio_vol_60` | 市场趋势、风险偏好 | 低波动溢价是否在小盘投机行情中反转？ |
| 动量、突破 | 市场趋势、成交额 | 缩量趋势和放量趋势的延续是否不同？ |
| 反转、跳空 | 波动、流动性、开盘吸收 | 反转是否只发生在高冲击但低持续成交条件？ |
| `margin_velocity` | 过去收益、市场风险偏好 | 融资加速是信息需求还是追涨拥挤？ |
| `smart_money_share` | 流动性、价格位置 | 聪明资金信号是否只在低关注股票中有效？ |
| 涨停衰减 | 封板质量、市场广度 | 普涨行情与孤立事件的衰减是否不同？ |
| 筹码集中度 | 换手率、趋势 | 集中度上升在趋势初期和末期的含义是否相反？ |
| 估值 | 市场趋势、规模 | 价值信号在风险偏好不同阶段的生效周期是否不同？ |

### 4.5 状态因子的验收标准

状态化因子必须同时报告：

- 基础因子无条件 IC。
- 每个状态下 IC、样本天数和有效股票数。
- 状态化后的整体 IC。
- 状态切换频率。
- 相比基础因子的增量 IC。
- 是否只由少数极端行情贡献。

状态样本不足 120 个交易日时，不应做强结论。

## 5. 方向三：评价增量信息，而不是继续比较单因子绝对 IC

### 5.1 建立核心风格基准集

先固定一组代表已有主要信息的基准因子，每类只保留 1～3 个代表：

1. 规模：`total_mv` 或规模 rank。
2. 估值：BP/PE/PS 中稳定代表。
3. 动量：20/60 日动量。
4. 反转：短期反转。
5. 低波动：`amplitude_20`、`idio_vol_60` 中的代表。
6. 流动性：换手率、Amihud 中的代表。
7. 市场暴露：`beta_60`、`corr_market_60`。
8. 日内结构：分钟 RV、尾盘压力代表。
9. 融资需求：`margin_velocity` 或融资残差代表。
10. 事件：涨停/极端收益代表。

核心集不是永久固定，应只在训练期根据稳定性更新。

### 5.2 新因子残差化

对每个日期做截面回归：

```text
candidate_t = alpha_t + core_factors_t @ beta_t + residual_t
```

同时报告：

- 原始 candidate IC。
- residual IC。
- 原始与 residual 的覆盖率。
- 对核心因子最高相关性。
- 加入 candidate 后组合/模型的样本外 IC 改善。

如果原始 IC 很高但 residual IC 接近 0，则它是已有风格的新表达，不应作为独立因子保留。

### 5.3 增量 IC 的最低要求

建议初始研究门槛：

- 连续因子样本外 `abs(mean IC) >= 0.01`；或
- 样本外 residual `abs(mean IC) >= 0.005` 且能显著改善组合稳定性；或
- 虽然 IC 较低，但显著降低换手、尾部风险或特定状态回撤。

门槛必须结合 HAC t-stat、fold 稳定性和多重检验结果，不能只按点估计判断。

### 5.4 去冗余标准

当前 0.95 阈值只能删除几乎完全重复的因子。推荐：

1. 计算逐日截面 Spearman 相关，再对日期求均值和分位数。
2. 对因子做层次聚类或图聚类。
3. 初始聚类阈值建议 0.75～0.85，不以保留固定数量为目标。
4. 同簇优先保留：样本外 IC 稳定、覆盖高、换手低、机制简单者。
5. 相关性低但 residual IC 为零的因子仍然不保留。

## 6. 方向四：重构因子表示层，避免过早 rank 和无效单调变换

### 6.1 当前问题

项目中大量基础因子在计算函数末尾直接调用：

```python
return cross_sectional_rank(raw_signal)
```

这有三个后果：

1. 原始幅度丢失。例如极端异常和普通高值都只剩百分位差异。
2. 后续时序 z-score 是对“历史截面排名”做 z-score，而不是对原始经济变量做 z-score。
3. 对 rank 后的值做 log/sqrt，再次 rank，不会产生新的排序信息。

### 6.2 推荐三层架构

#### 第一层：Primitive

尽量保留原始经济量，例如：

- 原始换手率和成交额。
- 原始分钟 RV。
- 原始净流入金额和占比。
- 原始筹码成本、集中度。
- 原始融资买入额和余额变化。

Primitive 不直接作为最终注册因子时，可作为模块内部共享计算结果。

#### 第二层：Transformation

允许的转换：

- 时序 z-score。
- 变化率、差分、加速度。
- 条件残差。
- 合理的 log/Box-Cox，但必须作用于原始偏态变量。
- 截面 winsorize。
- 截面 rank 或 z-score。

#### 第三层：Research Signal

最终因子应表达清楚机制，例如：

```text
原始融资买入额
 → 对成交额和规模取残差
 → 相对自身历史标准化
 → 与价格确认状态组合
 → 输出融资积累信号
```

### 6.3 明确禁止的变换

禁止新增以下模式：

```text
rank(x) → log → rank
rank(x) → sqrt → rank
rank(x) → 单调幂函数 → rank
rank(x) 与自身单调变体同时保留
仅改变正负方向后注册为新因子
```

现有 `microstructure_transform.py` 中的 log/sqrt 变体应进入清理候选。时序 z-score 变体只有在基础因子的原始幅度仍被保留时才有合理意义。

### 6.4 建议的输出策略

对于重要 primitive，最多保留以下三类之一或少量组合：

| 输出 | 含义 | 适用场景 |
|---|---|---|
| `raw_winsorized` | 保留幅度 | Pearson、非线性模型 |
| `xs_rank` | 保留横截面顺序 | Rank IC、稳健选股 |
| `ts_surprise_then_xs_rank` | 个股历史异常后的截面比较 | 当前体系优先推荐 |

不得为每个 primitive 自动生成全部变体。每个变体都必须有独立假设。

## 7. 方向五：重构耦合因子，禁止无约束公式组合

### 7.1 当前 coupling 的主要风险

当前约有 125 个 coupling 因子，常见形式包括：

- 两个 rank 相乘。
- 两个 rank 相减形成背离。
- 三个因子共振。
- 高低状态的经验加权和。

这些形式并非天然错误，但容易产生：

- 同一低波动/换手风格的重复表达。
- 公式复杂但没有增量 IC。
- 在全样本上碰巧有效，样本外不稳定。
- 组合中某一个强基础因子贡献全部 IC。

### 7.2 耦合因子必须属于以下机制之一

#### A. 确认 Confirmation

一个信号需要另一个独立信息源确认：

```text
price_momentum × volume_confirmation
margin_demand × price_absorption
chip_migration × turnover_confirmation
```

要求：两个输入必须来自不同信息机制，且分别报告单独 IC。

#### B. 背离 Divergence

两个通常共同变化的量发生异常偏离：

```text
price_rank - flow_rank
price_change - chip_cost_change
return - amount_expected_return
```

优先使用残差而不是简单 rank 相减。

#### C. 效率 Efficiency

单位投入产生多少价格结果：

```text
price_impact / net_flow
return / turnover
realized_vol / trading_amount
```

分母必须经过稳定处理，并进行流动性分层，避免小分母爆炸。

#### D. 状态门控 Gating

基础信号只在某种状态激活：

```text
reversal_signal × high_shock_state
momentum_signal × trend_market_state
lowvol_signal × risk_off_probability
```

状态必须先经过独立条件 IC 验证。

#### E. 时序领先滞后 Lead-Lag

一个信息源领先另一个信息源：

```text
flow_t-1 → price_t:t+3
chip_shift_t-5:t → price_t:t+5
margin_acceleration → turnover_confirmation
```

必须明确每个变量的时间位置，禁止隐含未来数据。

### 7.3 耦合因子拆解要求

每个新 coupling 必须生成研究报告表：

| 指标 | Input A | Input B | Coupling |
|---|---:|---:|---:|
| 1d OOS IC |  |  |  |
| 3d OOS IC |  |  |  |
| 5d OOS IC |  |  |  |
| 10d OOS IC |  |  |  |
| ICIR/HAC t |  |  |  |
| 覆盖率 |  |  |  |
| 与核心因子最高相关 |  |  |  |
| residual IC |  |  |  |

只有 coupling 在样本外显著优于最佳单输入，或提供稳定 residual IC，才允许保留。

## 8. 方向六：因子与预测 horizon 必须匹配

### 8.1 当前 target 定义

当前标签定义为：

```text
label_ret_Nd[t] = open[t+1+N] / open[t+1] - 1
```

即 T 日收盘后得到信号，T+1 开盘买入，持有 N 个交易日后开盘卖出。

### 8.2 建议的 horizon 映射

| 因子类型 | 主 horizon | 原因 |
|---|---|---|
| 尾盘压力、开盘吸收、分钟订单失衡 | 1d | 信息衰减快 |
| 单日成交冲击、资金流 surprise | 1d/3d | 短期价格发现 |
| 融资需求持续性、事件衰减 | 3d/5d | 杠杆需求和事件反应需要数日扩散 |
| 筹码迁移、波动压缩、趋势效率 | 5d/10d | 结构变化较慢 |
| 估值、低波动、质量风格 | 10d/20d | 风格溢价不适合只用 1d 判断 |

### 8.3 禁止跨 horizon 取绝对值后直接评分

必须保存：

- `ic_mean_1d/3d/5d/10d`
- `ic_std_1d/3d/5d/10d`
- `icir_1d/3d/5d/10d`
- 每个 horizon 的方向和 fold 稳定性
- IC 衰减曲线

如果 1d 为负、5d 为正，应解释为反转到延续的时间结构，而不是通过 `abs()` 合成一个“高质量”分数。

## 9. 因子评估规范

### 9.1 样本切分

任何使用 target 的筛选都必须在训练区间内部完成。

推荐 walk-forward：

```text
Fold 1：训练 2022 → 测试 2023H1
Fold 2：训练 2022-2023H1 → 测试 2023H2
Fold 3：训练至 2023H2 → 测试 2024H1
...
```

具体日期可结合现有季度模型切分，但必须满足：

- 测试期标签从未参与因子方向、窗口、阈值或去冗余选择。
- 3d/5d/10d 重叠标签使用 purge/embargo，至少隔离一个最大 horizon。
- 任何调参结果都只在下一段时间评估。

### 9.2 连续因子的基础质量门槛

建议初始门槛：

- 2022 年后 NaN 比例不高于 20%。
- 每日有效股票数中位数不低于 `max(300, 股票池 30%)`。
- 每日有效股票数 P10 必须记录。
- 有效 IC 日期不少于 250；新数据源最少不低于 120。
- 截面非唯一值数充足，不能长期退化为常数或少数离散值。
- 日变化率不低于 1%，时间编码类除外。

事件因子不适用统一覆盖率门槛，必须进入独立事件研究流程。

### 9.3 必报指标

每个 factor × horizon × fold 至少报告：

- Rank IC mean、std、ICIR。
- Pearson IC mean、std。
- Newey-West/HAC t-stat。
- IC 正比例、年度/季度 IC。
- 有效日期数。
- 每日有效股票数中位数和 P10。
- 数据覆盖率。
- IC 自相关与衰减。
- Top-Bottom 10% 收益。
- 多空收益换手和成本后收益。
- 与核心因子最高相关性。
- 对核心因子残差化后的 IC。
- 各 fold 方向一致率。

### 9.4 多重检验

当一次研究测试数十或数百个候选时，最大 IC 必然存在数据挖掘偏差。必须至少使用一种修正：

- Benjamini-Hochberg FDR。
- 日期 block bootstrap。
- Deflated Sharpe/IC 思路。
- Reality Check 或同类候选集修正。

禁止只报告候选集中最好的前 10 个而忽略总测试数量。

### 9.5 稳定性优先于峰值

一个推荐保留的因子通常应满足：

- 至少 3/4 的样本外 fold 方向一致。
- 不是只由单一年份或单个季度贡献。
- 删除最强 5% 日期后仍有同方向 IC。
- 在主要流动性分组中方向不发生不可解释的完全反转。
- 相比最接近的旧因子存在 residual IC 或成本改善。

## 10. 可交易性与标签规范

### 10.1 必须平行评估的标签

至少同时比较：

1. 原始 open-to-open 收益。
2. 截面 winsorize/rank 收益。
3. 市场和规模中性化残差收益。
4. 可交易股票池收益。

行业中性化只有在取得 PIT 行业映射后才能启用。

### 10.2 可交易过滤

根据数据可得性逐步加入：

- T+1 买入日停牌。
- T+1 开盘涨停或无法合理买入。
- 卖出日跌停或无法合理卖出。
- 上市时间过短。
- 成交额过低。
- 极端价格或数据异常。

如果缺少精确过滤数据，应明确标注“理论 IC”与“可交易 IC”的差异，不得混用。

### 10.3 缺失标签不得填零

模型训练和评估中，缺失 target 应通过 mask 排除。将缺失收益填 0 会把未知结果错误解释为截面平均收益，并污染 loss、IC 和收益评估。

## 11. 新因子注册与元数据要求

### 11.1 注册信息必须扩充研究字段

现有 `FactorSpec` 至少包含 name、description、category、thesis、dependencies。研究记录还应在报告或独立 manifest 中保存：

```yaml
name: margin_buy_demand_residual_20
primitive_sources:
  - margin_detail.parquet.margin_buy_amount
  - daily.parquet.amount
  - finance.parquet.total_mv
primary_horizon: 5d
secondary_horizons: [3d]
expected_direction: positive
mechanism: abnormal leveraged demand not explained by activity or size
controls:
  - log_total_mv
  - amount
  - past_return_5d
benchmark_factors:
  - margin_buy_momentum_5d
  - margin_velocity
failure_modes:
  - chase effect
  - sparse margin universe
  - T+1 data availability
```

### 11.2 命名约定

名称应直接体现信息与变换：

```text
<primitive>_<transformation>_<window>[_<condition>]
```

推荐：

- `turnover_surprise_20`
- `margin_buy_residual_20`
- `chip_cost_shift_surprise_20`
- `close_pressure_residual`

避免：

- `deep_alpha_v2`
- `enhanced_factor`
- `smart_combo_3`
- 只靠后缀区分但无法看出机制的名称。

### 11.3 thesis 写法

合格 thesis 应包括：

1. 原始信息。
2. 去除了什么机械关系。
3. 为什么剩余部分可能被延迟定价。
4. 预期生效周期。
5. 主要失败场景。

## 12. Claude/开发代理执行流程

当 Claude 或其他开发代理接手本项目时，默认任务是清理和压缩现有因子库，而不是开发新因子。首先执行“最高优先级指令”中的五层减法和阶段门禁。

只有在 30～80 个核心候选集已经形成、缺失信息机制已经得到证据确认，并且用户明确要求进入新增阶段后，才按以下顺序执行新因子研究。

### Step 1：盘点已有因子

- 搜索注册表和 factor 文件。
- 找到同 primitive、同窗口、同变换、同机制因子。
- 查询 `fac_select_meta.json` 中已有因子的统计。
- 列出最接近的 3～5 个 benchmark。

### Step 2：写研究假设，不立即写代码

输出：

- primitive。
- transformation。
- expected direction。
- primary horizon。
- controls。
- failure modes。
- 与旧因子的预期增量。

### Step 3：检查 PIT 与数据到达时间

- 只使用 `skill.md` 白名单数据源。
- 检查是否需要 shift。
- 禁止静态快照回填历史。
- 禁止未来窗口和全样本标准化。

### Step 4：先做最小原型

- 只实现最简单、最可解释版本。
- 不同时生成多个窗口和多个单调变换。
- 尽量复用 primitive 计算，避免重复 I/O。

### Step 5：执行质量与增量评估

- 覆盖率和截面数。
- 分 horizon IC。
- walk-forward OOS。
- 对 benchmark 的 residual IC。
- 换手和成本。

### Step 6：决定保留、重做或放弃

- `keep`：稳定且有增量。
- `conditional`：仅特定状态有效，进入状态化研究。
- `redundant`：被已有核心因子解释。
- `unstable`：方向跨 fold 翻转且无法解释。
- `invalid`：覆盖/PIT/性能不合格。

### Step 7：记录失败结果

失败因子也必须记录假设、实现和失败原因，避免未来重复研究同一路径。

## 13. 优先研究路线图

### P0：评估体系和重复因子清理

在新增因子前完成：

1. 保存每个 horizon 的 IC 明细，不再只保存聚合绝对值。
2. 增加每日有效股票数门槛和覆盖率统计。
3. 删除或降级 `mean(abs(daily IC))` 作为 quality 的权重。
4. 修复不同 NaN 掩码下的相关矩阵计算。
5. 删除 `rank → log/sqrt → rank` 单调重复变体。
6. 将监督式因子筛选移入 walk-forward 训练窗口。
7. 去掉必须保留 500～620 个因子的数量约束。

### P1：高潜力信息源的 surprise/residual 化

> **进入条件：P0 已完成，核心因子集合已经形成，并且审计报告证明下列信息机制存在缺口。未满足条件时，禁止执行 P1。**

建议先开发并评估：

1. `margin_buy_demand_residual_20`
2. `margin_acceleration_price_confirmation_5`
3. `turnover_surprise_size_neutral_20`
4. `big_order_flow_surprise_20`
5. `close_pressure_residual`
6. `opening_gap_absorption`
7. `chip_cost_shift_surprise_20`
8. `chip_concentration_price_divergence_10`

每个方向先只做一个主窗口版本。

### P2：状态依赖

> **进入条件：已有因子的方向翻转已通过条件 IC 得到可重复证据。不得为了提高公式复杂度而直接生成 gated factor。**

优先验证：

1. 低波动因子 × 市场风险偏好。
2. 动量/反转 × 市场趋势和成交状态。
3. 融资加速 × 过去收益位置。
4. 涨停衰减 × 市场广度和封板质量。
5. 资金流 surprise × 个股流动性。

只有条件 IC 稳定后才注册 gated factor。

### P3：核心因子集与增量选择

P3 中的核心压缩工作实际应与 P0 同步启动，并优先于任何新增开发：

1. 从 768 个因子压缩出约 30～80 个核心代表。
2. 按信息机制而非文件类别聚类。
3. 对现有因子先做 residual IC，再决定保留与删除。
4. 对未来新因子继续统一执行 residual IC。
5. 使用滚动训练 IC 加权、Ridge 或其他强正则简单模型建立基线。
6. 只有在简单模型确认增量后，再交给复杂 MLP 学习非线性。

## 14. 最终验收清单

新因子合入前，逐项确认：

- [ ] 有明确且可证伪的经济/微观结构假设。
- [ ] 指定了 primary horizon，未事后按最好 horizon 挑选。
- [ ] 只使用 PIT 合格数据，数据到达时间正确。
- [ ] 未依赖静态快照回填历史。
- [ ] 使用原始 primitive 构造，不是在 rank 后做无效单调变换。
- [ ] 与最接近的旧因子有明确区别。
- [ ] 连续因子 NaN、有效股票数、截面方差和日变化率合格。
- [ ] 报告逐 horizon、逐 fold、逐年度 IC。
- [ ] 使用 HAC 或 block bootstrap 处理时序相关。
- [ ] 经过多重检验修正。
- [ ] 样本外方向稳定，或状态翻转得到明确解释。
- [ ] 对核心因子残差化后仍有增量信息。
- [ ] 多空收益在合理成本后仍有意义。
- [ ] coupling 优于最佳单输入，而非只复制强输入。
- [ ] 记录失败场景和可能失效的市场状态。
- [ ] 没有为了达到因子数量目标而保留弱因子。

## 15. 核心结论

当前因子体系下一阶段的主要增量，不会来自更多 RSI、MACD、振幅、换手率和资金流比例的排列组合，而更可能来自：

1. **异常值**：相对自身历史有多异常。
2. **条件残差**：剔除规模、成交、收益和波动后还剩什么。
3. **动态变化**：速度、加速度、持续性和衰减。
4. **状态依赖**：同一信号在何种行情下有效或反转。
5. **增量信息**：相对核心风格是否仍有 residual IC。
6. **时间匹配**：让分钟冲击预测短周期，让筹码/估值预测中周期。
7. **可交易性**：最终优化的是成本后的样本外收益，而不是全样本绝对 IC。

后续因子开发应以“更少但更独立、更稳定、更可解释”为目标，而不是继续扩大因子总数。
